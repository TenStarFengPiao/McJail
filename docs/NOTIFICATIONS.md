# 管理员通知与定时提醒

默认管理员 QQ 为 `3244104494`。机器人以 NapCat 事件的真实 `user_id` 校验权限，不接受昵称、正文或模型声称的身份。仅可私聊下达指令，所有群聊均静默，所有管理回执私聊发送者。其他用户不能创建、确认、取消或补发通知。

## 创建与确认

例如在北京时间 2026 年 10 月 14 日发送：

```text
明天7:30发信息提醒所有同学，明天上午八点去四教参加毕业答辩会议。
```

预览区分发送时间 `2026年10月15日 07:30` 与活动时间 `2026年10月15日 08:00`，并给出好友人数。正式正文为：

```text
会议提醒
时间：2026年10月15日 08:00
地点：四教
事项：参加毕业答辩会议。
```

回复 `确认通知 N...` 生效。任务号是完整的 `N` 加16位标识，必须复制预览中的实际号码，不是示例编号。草稿保存30分钟，可跨重启确认；过期或计划时间已过去时要求新预览，不自动顺延。补充缺失信息必须在同一私聊或同一群会话中进行，新的预览会取代旧草稿。

支持单次、立即、每天固定时间、每周指定星期和时间，周期任务可提供结束日期，否则持续至取消。每天/每周的活动时间保存为发送日期后的天数与时刻，每次确定性计算，不由模型重新生成。时间均采用北京时间，相对日期以入站指令时间为准。

“所有同学／所有用户／全员”均指全部 QQ 好友，而非群成员。读取名单去重、排除机器人自身；确认前复核接收者，新增好友不自动加入。指定接收者必须提供好友 QQ 号，不按昵称猜人。名单获取失败、为空或指定人不是好友，任务不能生效。

正文仅根据管理员输入整理，不添加学校事实、个性化称呼或知识库来源。地点和活动时间没有提供时可省略，不能编造；发送时间、对象、通知内容或周期含糊时先追问。否定请求、引用话语、讲解示例不应被识别为创建指令。

## 管理命令

| 命令 | 行为 |
| --- | --- |
| 查看通知任务 | 最近100项任务与下一次时间 |
| 查看通知 N... | 任务状态与最近10次执行、原正文和逐人明细 |
| 查看通知 R... | 某次执行的回执与原正文 |
| 确认通知 N... | 激活有效草稿；必须精确命令 |
| 取消通知 N... | 停止后续接收者和未来周期，不能撤回已提交消息 |
| 补发通知 R... | 生成补发风险预览，不立即发送 |
| 确认补发 R... | 明确确认后补发失败、跳过或未知页，已确认页不重发 |

修改可以自然语言指定任务号，例如“将 N... 的地点改为五教”。修改形成新预览，确认后取消原任务并激活新任务。失败或未确认的修改不影响原任务。

## 调度和发送契约

`run-bot` 同时启动到期扫描与串行发送工作循环；`run-all` 自动包含，不需要提醒服务、队列或额外部署模板。每5秒扫描，通知发送默认间隔1秒。服务停止期间不发送，恢复后处理数据库中的到期任务。

补发窗口为计划时间后30分钟（边界包含30分钟）。周期任务只考虑最近一轮，不集中发送积压历史；超过窗口跳过并给出报告。大批次仍受窗口限制，来不及发送的接收者会跳过；可通过发送间隔调整吞吐。

每次运行保存一份不可变正文，按2000字符切成固定页，所有接收者使用同样的正文、分页和顺序。逐人页先保存 `sending`，再调用 QQ，最后保存回执；数据库事务不跨越网络请求。SQLite 写锁、任务/计划时间唯一约束和运行租约防止并发创建或执行。

明确接口拒绝最多尝试3次，重试间隔为30、120秒，并受窗口限制。超时、断线、响应无法确认或进程在发送中退出，记为结果未知，不盲目重发。某人的前页未确认时不发送后页，其他人的发送继续。已确认页跨重启不会重发。

报告统计总人数、接口确认人数、失败人数、结果未知人数与跳过/待发送人数。QQ接口接受不等于用户已读。报告只发摘要，正文和逐人明细通过查看命令分页展示；报告失败不触发学生通知重发。

手动补发保留原接收名单与正文，可为失败、跳过及未知项目重新打开30分钟窗口；结果未知的接收者可能收到重复通知，必须先预览风险再明确确认。取消的任务不可补发。

## 数据与配置

新增 `notification_tasks`、`notification_runs`，复用 `delivery_attempts` 保存命令回执和逐页发送状态；通知执行不向接收者写入 `chat_turns`；管理员本人的查询与预览回复成功后可以保存完整对话。迁移仅新增表和版本记录，不删除旧业务表或重建知识向量。加入群转发后，新数据库共有16张必要表。

```dotenv
NOTIFICATION_ADMIN_QQ=3244104494
NOTIFICATION_SEND_INTERVAL=1
```

通知管理现在是统一 Agent 的功能。管理员可说“有哪些通知待发”“明天早上有什么提醒”“那条会议通知发了吗”，工具按数据库真实状态查询；默认待发不含草稿、已完成和已取消任务。列表默认20条，可查看后续页，每页最多50条。查询时间是北京时间左闭右开范围。状态追问必须重新查询，不凭历史回答。

自然语言取消先展示取消预览，再回复 `确认取消通知 任务号`。取消预览复用交付回执保存，30分钟有效，确认时复核任务快照；已有精确 `取消通知 任务号` 仍直接生效。修改草稿需要明确原任务号，过期或跨会话草稿不能自动复用。

独立通知模型解析器已移除。统一 Agent 使用三个工具查询任务、读取详情和准备变更，每轮最多一个变更；确认、实际取消、周期计算和发送仍由固定代码执行。CLI 用户号不能获得QQ管理员权限。只要本轮使用通知工具，完整回复私聊管理员，预览文本由服务端原样生成。模型中断不撤销已保存草稿，也不自动激活任务。详见 [统一 Agent 说明](UNIFIED_AGENT.md)。

发送间隔允许0至30秒，避免间隔超过执行租约；生产默认1秒。

本地测试使用真实临时 SQLite、模拟时钟和模拟 QQ 接口；不向实际好友发送验证消息。上线前备份数据库，使用新版本首次连接完成新增表迁移，无须清空或重新 Embedding。
