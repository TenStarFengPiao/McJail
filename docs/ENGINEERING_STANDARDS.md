# 工程规范

- 一个生产问答链路：入口只调用 AssistantService；Agent 工厂仅使用 LangChain 公开 API，不手写图或工具循环。
- 模型只有只读 search_knowledge，QQ 发送属于入口适配职责，不作为 Agent 工具。
- 公共接口提供中文契约注释，说明输入、返回、错误与事务边界；复杂逻辑解释原因，避免逐行复述代码。
- 领域 DTO 放在 rag/models.py，SQLAlchemy 映射放在 persistence/models.py；工具返回字典证据，不返回 ORM 实体或 Session。
- 每请求独立数据库工作单元，禁止并发共享 Session。文档、块和两种索引共同提交或回滚，聊天一次保存完整问答。
- 在线 Embedding 不静默降级；Hash 只能显式注入。Rerank 可以降级，并通过普通日志或内部诊断记录。
- 知识库与对话分别保存普通数据，不把工具消息、checkpoint 或大工作流状态持久化。
- 配置与客户端对象区分，模型名是字符串，实际模型名和维度决定向量可比性。
- 测试使用临时数据库、离线脚本聊天模型、显式 Hash 和模拟网络，不触碰实际业务数据。
- 依赖由 pyproject.toml 声明、uv.lock 锁定；提交前执行全量测试、Ruff、格式、锁检查和 smoke。覆盖率至少 80%。
- 不新增没有当前用途的业务分层、通用容器、队列和恢复系统。删除功能时一并删除运行入口、专属测试与旧文档。
