# 统一 Agent 与通知工具

QQ 和 CLI 共享一个 LangChain `create_agent()`。RAG 是知识检索工具，不再代表整个助手；文件准备、北京时间、市区天气和管理员通知管理是其他能力。没有自定义工作流、第二次通知模型解析或模型控制的发送循环。

## 请求与权限

NapCat 入口从真实事件建立 `RequestContext`，绑定 QQ 用户号、会话标识、原消息ID和接收时间。服务复核这些字段与请求参数一致；模型只看必要的时间与草稿上下文，不能选择身份。默认管理员为 `3244104494`。只有真实QQ管理员注册通知工具，服务层再次校验账号。CLI 的 `--open-id` 仅用于聊天隔离，不能开启通知权限。

自然语言统一进入 Agent，包括“有哪些通知待发”“明天早上有什么提醒”和“那条会议通知发了吗”。只有明确人工确认与已有精确管理命令走兼容入口。模型判断应调用哪项能力，但不能确认、发送或直接取消任务。讨论示例和明确否定表达有保守否决检查，这个检查不替代自然语言意图理解。

## 工具契约

| 工具 | 参数与返回 | 边界 |
| --- | --- | --- |
| `list_notification_tasks` | `status=pending`、`start/end`、`keyword`、`page=1`、`page_size=20`；返回任务摘要、总数、下一页 | 状态和时间来自数据库，默认不含草稿；最多50条/页 |
| `get_notification_task` | 任务号或执行号，`include_recipients=false`；返回候选正文、排期和执行回执 | 只有明确索要时才展开逐人回执，QQ接口确认不是已读 |
| `prepare_notification` | `action=create/update/cancel/retry`，结构化 `spec` 和/或任务/执行号；返回固定预览 | 不激活、不发送；每条消息最多一个通知变更 |

`pending` 包含已生效且仍有可执行计划的任务，以及补发期限内待执行或执行中的批次；单次任务已完成排期但批次尚未完成时仍显示。未确认草稿使用 `draft` 或 `clarifying` 查询。时间范围是北京时间左闭右开区间，无偏移的ISO时间按北京时间解释。事项、标题、地点支持关键词筛选。已过期草稿在查询中标注过期，不需要修改数据库。

发送时间与活动时间分别保存。“明天7:30提醒所有同学，8点去四教开会”对应发送07:30、活动08:00。“明天”以原消息收到的北京时间解析；校验过期时间使用当前服务时钟。每天与每周仍使用现有周期契约，周期发送不再调用模型。

当前会话未过期草稿作为数据提供给 Agent。补充或修改必须引用任务号并提供完整替代候选；多个草稿先澄清。修改已生效任务生成新预览，确认时原子替换；补全修改草稿保留其最初指向的已生效任务，不让旧任务继续发送。

## 确认与交付

- 创建／修改：`确认通知 任务号`。
- 自然语言取消：预览后 `确认取消通知 任务号`。预览30分钟有效，任务状态、排期或正文变化时重新预览。
- 旧精确取消命令：`取消通知 任务号`，仍直接取消。
- 手动补发：风险预览后 `确认补发 执行号`，明确提示未知结果可能重复。

确认必须是管理员本轮完整的精确文本，引用、例子、模型输出均不能生效。确认工具不注册到 Agent。所有预览使用服务端固定文本，不接受模型改写确认命令、人数或时间；一轮生成通知预览时优先交付该预览，其他问题可继续追问。

只要本轮使用通知工具，整个回复私聊管理员。所有群聊入站均只采集、不回复，不进入 Agent。`AssistantResponse.reply_target` 默认 `conversation`，通知管理使用 `private`；交付快照保存目标，旧快照缺少字段时沿用原会话规则。管理员完整对话在全部交付成功后保存，不为接收者创建问答。

草稿和回复是独立事务。模型在草稿保存后失败仍返回已保存的原始预览；重启重放同一消息可恢复预览，不再次调用模型建任务。回复失败不会激活任务，草稿仍可查询。数据库和模型异常不暴露凭据或原始网络响应。

## 调度与兼容

调度器仍随 `run-bot` 启动，每5秒扫描到期任务，使用领取、租约和短事务保护并发。每次运行冻结正文、名单和分页，发送、失败重试、结果未知、补发窗口和执行报告遵循原有规则。模型不决定运行批次的内容或接收者。

取消预览复用 `delivery_attempts`，不新增表；已有任务、执行批次、知识向量和聊天记录保持兼容。现有旧查询、确认、取消和补发命令保留。数据库不需要清空或重新Embedding。

本轮只改本地代码与文档，未发布服务器，未发送真实QQ验证消息。天气服务在服务器上的区县定位连接问题不属于本次统一 Agent 改造。

统一 Agent 前一阶段本地验收：265项全量测试通过，覆盖率95.59%；Ruff、格式检查、锁文件检查和CLI smoke通过。真实聊天模型在独立临时库验证了待发查询、发送07:30与活动08:00分别提取、明早时间范围查询及取消预览；QQ传输全部模拟，没有运行真实通知批次。

当前群入口全局静默：任何群消息均不进入问答或确认命令链路。来源群按确认规则收集固定60秒窗口，管理员私聊要求生成预览并确认版本后，由独立工作器发布。统一 Agent 新增 query_group_forwarding、prepare_group_forwarding、control_group_forwarding，仅真实QQ管理员获得；模型没有确认或发送工具。新增四张群转发表，迁移版本7，新库16表；通知调度不变。详细交互、原生转发限制及失败恢复见 [群转发说明](GROUP_FORWARDING.md)。
