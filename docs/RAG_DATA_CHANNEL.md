# RAG 数据通道

文档导入：UTF-8 原文 → 规范化 → 按长度分块 → 事务外批量在线 Embedding → 短事务原子提交正文、关键词和向量。

原件关联：同一文档 ID 下保存原始 PDF / Word 的文件名、字节和 SHA256；可随语料一起原子导入或在后台补传。原件不参与分块和 Embedding，重建检索索引不覆盖原件。

原件交付：同一会话最近引用的文档 ID 与版本 → 消除多文档歧义 → 检查原件完整性 → QQ 私聊上传原始字节。明确标题不存在时不退回发送其他文档。通过 NapCat 支持的 Base64 文件资源传输，不依赖机器人和 NapCat 共享本地路径。

交付资料：原始模板 → `delivery_resources` 登记标题、主题词和届别 → 相关提问或索要时匹配 → 附带原始文件。整个登记过程不调用 Embedding；模板内容不进入检索正文。通过 `resource_id` 保存同会话交付引用，供后续索要定位。

查询：查询改写 → 同模型同维度向量与 BM25 → RRF → 可选云端 Rerank（失败沿用 RRF） → 来源校验 → 4200 字符预算 → Agent 可读证据和结构化来源。

小语料在完整证据能放进预算时直接提供整库证据；云端 Rerank 异常沿用 RRF 顺序，Embedding 异常不使用 Hash 替代。来源校验不等同于语义正确性证明。

重建按原文、源文件、已有块顺序恢复，保留文档 ID 并递增版本。任一步失败回滚旧文档和全部索引。切换模型不自动重建，必须部署前显式执行 reingest-doc。

两条查询路径使用相同资料范围，不按培养类型过滤。单召回通道故障允许另一通道继续，两个通道都故障才报检索失败。查询接口仅接受问题文本，不接受无效的 intent/profile。QQ 回复和保存的答案为纯文本。
